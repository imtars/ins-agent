# 合成保险数据的语义与限制（M1.1）

这套数据是可重复的演示世界，不是精算模型，也不是任何保险公司的历史记录。固定种子 `202609` 只用于重建相同记录。

## 出险与暴露时间

每张保单最多生成 **一条**理赔；因此 `claims.policy_id` 唯一。它模拟观察期内是否发生一次可赔事故，不能作为重复出险次数模型。观察窗口固定为 2026-01-01 至 2026-08-31（均含）。保单期限为 365 天；健康险另扣除产品文档注明的等待期。

先按产品类别、客户 `risk_score`、年龄、区域和产品变体的内部因子计算完整一年暴露的概率 `p_annual`。只对窗口内且已过等待期的 `exposure_days` 抽样：

```text
p_observed = 1 - (1 - p_annual) ^ (exposure_days / 365)
```

因此其他条件相同时，暴露 60 天的保单比暴露 240 天的保单更少出险。基础频率是为了在默认 30,000 张保单下形成规格要求的数千条理赔而设置的演示参数，没有真实保险统计含义。

## 产品与文档

12 款产品各有明确的保障责任、责任免除、等待期或免赔/自付条件、年度限额。保障范围较广的变体使用较高的内部出险与赔款金额因子。这些因子只在生成器和 synthetic manifest 中；`products` 业务表只保存产品代码、名称、类型和基础保费。未来 SQL 查询需要从保单、理赔和赔付记录计算观察结果，不能读取生成器参数。

`claim_amount` 是生成器给出的**核定演示金额**，不是逐项医疗账单或维修发票。生成器没有逐笔执行条款的免赔、自付或限额理算，也没有事故原因字段。文档说明的是演示产品规则；它不能作为某条理赔已符合具体责任的证明。已结案理赔的付款总额等于该核定金额，未结案或拒赔理赔没有付款。

SQL 与条款合并分析时，只能说“某产品在合成运营数据中观察到较高赔付表现，同时其演示条款覆盖范围较广”等有证据的事实。**不能仅凭二者相关就声称条款导致较高赔付率。**公开中保协草案没有与这些合成产品的 `product_code` 对应关系。

## 指标解释

季度理赔频率应考虑季度内的有效暴露天数。若计算季度赔付率，分母应使用按保单有效天数分摊的已赚保费，而不是直接拿全年保费与季度赔付作比。M3 的 SQL gold case 已按这两个区间重叠天数计算已赚保费；已发生赔款排除 denied，现金赔付按付款日期另列。业务表没有结构化等待期，SQL 单独计算的在保暴露年不是扣除等待期后的可出险暴露年，不得混用这两个频率口径。本数据每张保单最多一条理赔。
